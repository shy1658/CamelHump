## 二、我方立场与论证（审核方会追问的部分）

### 2.1 核心判断：不符合"向境内公众提供"

《生成式人工智能服务管理暂行办法》第二条：

> 利用生成式人工智能技术**向中华人民共和国境内公众提供**生成文本、图片、音频、
> 视频等内容的服务（以下称生成式人工智能服务），适用本办法。
> ……行业组织、企业、教育和科研机构、公共文化机构、有关专业机构等研发、应用
> 生成式人工智能技术，**未向境内公众提供生成式人工智能服务的，不适用本办法的规定。**

逐项对照：

| 构成要件 | 本应用情况 | 说明 |
| --- | --- | --- |
| 是否向**境内公众**提供 | **否** | 无服务器、无运营主体、无服务化接口。应用是一个离线工具，不是服务 |
| 是否使用生成式 AI 技术 | 是 | 文本生成 |
| 是否具备**提供**的能力 | **否** | 无网络权限、无网络 API，物理上无法服务任何外部用户 |

同法第二十二条对"提供者"的定义是「利用生成式人工智能技术**提供**生成式人工智能
服务（包括通过提供可编程接口等方式提供生成式人工智能服务）的组织、个人」。
本应用不提供任何可编程接口，也不以自己的名义对外提供生成能力。

**结论**：不适用该办法 → 不触发生成式 AI 服务备案、也不触发应用/功能登记。

### 2.2 算法备案的前置条件同样不成立

《互联网信息服务算法推荐管理规定》的算法备案义务，
前置条件是「具有舆论属性或者社会动员能力的**互联网信息服务**」。

- 本应用不是互联网信息服务（不通过互联网向公众提供服务）；
- 单机离线工具不具备舆论属性或社会动员能力（无公开发布、无内容流转、
  无面向不特定公众的传播渠道）；
- 应用不提供内容分享、发布、评论、通讯群组等任何具有传播属性的功能。

**结论**：不落入算法备案的适用范围。

### 2.3 为什么"应用通过市场分发"不改变结论

这是审核方最可能反问的一点，需要正面回答：

| 可能的追问 | 我方答复 |
| --- | --- |
| 通过应用市场公开发布，算不算"向公众提供"？ | **分发的是工具，不是服务。** 类比：离线图像处理软件、单机杀毒软件、PDF 阅读器同样通过应用市场公开分发，但都不因分发而成为互联网信息服务 |
| 应用有 AI 对话功能，用户能"用"AI 生成文本 | **AI 能力的使用对象是用户本人，不是应用运营者。** 服务关系不成立，因为应用方不提供该能力，只提供本地计算引擎 |
| 模型是"应用提供的" | **不是。** 模型权重由用户自行获取并导入，应用安装包内模型文件为 0 个，开发者不掌握、不分发、不控制模型内容（见 `MODEL-PROVENANCE.md`） |

### 2.4 单机 APP 的官方豁免情形对应

华为对"单机应用"的官方定义：

> 单机应用：未通过连接公共互联网提供互联网信息服务的移动应用程序。

官方列举的豁免场景中，本应用属于**「完全离线型：断网后，APP 内所有功能和链接均可正常访问」**。

这一点有**可执行的验证方式**（而非仅凭声明）：

- 开启飞行模式 → 导入 GGUF 模型 → 加载 → 对话 → 停止生成 → 切换模型 → 修改参数，
  全部功能正常；
- 应用内唯一的联网入口是「隐私政策」链接，通过**系统浏览器**打开，
  由系统进程发起请求，**不经应用进程**，且属于官方豁免情形中的
  「仅隐私协议托管联网型」。

> ⚠️ 提交前务必完成飞行模式实测并录制视频。审核员实测是标准动作。

## 五、备用问法（若 AGC 前台无法受理技术咨询）

若审核方一线无法就算法备案适用性给出明确答复，可通过以下渠道升级：

1. **AppGallery Connect 工单** — 在版本审核处提交「审核咨询」类工单，附本文材料；
2. **华为开发者论坛 / HMS 开发者问答** — 以「单机离线生成式 AI 应用是否需要算法备案号」
   为题提问，通常有法务或审核团队回复；
3. **属地网信部门** — 若结论直接决定能否上架，可向注册地网信办书面咨询。
   咨询要点见下：

```
咨询要点（致属地网信部门）：
1. 本应用为单机离线工具，无服务器、无网络权限、无网络通信代码，
   推理全部在用户设备 CPU 本地完成，模型由用户自行导入；
2. 《生成式人工智能服务管理暂行办法》第二条以「向境内公众提供」为适用前提，
   请确认本应用是否属于该情形；
3. 若不属于，是否可确认无需办理生成式人工智能服务备案、应用或功能登记，
   以及无需履行《互联网信息服务算法推荐管理规定》项下的算法备案义务。
```

## 六、⚠️ 结论的适用边界

本材料的论证**完全建立**在以下前提上。任一前提变化，结论须重新评估：

| 前提 | 破坏后的后果 |
| --- | --- |
| 应用无网络权限、无网络代码 | 前提不成立 → 须走服务备案或应用登记路径 |
| 安装包内不含模型权重 | 属"应用自行提供模型" → 须走服务备案路径 |
| 用户自行获取模型、应用不分发 | 同上 |
| 应用不提供任何可编程接口 | 若开放 API → 构成"提供者" |
| 不具备舆论属性 / 社会动员能力 | 若加入公开发布、分享功能 → 触发算法备案评估 |

**代码层面的守护**：上述前提不是口头承诺，而是由 `module.json5`（无 requestPermissions）
与 `oh-package.json5`（`dependencies: {}`）在构建层面固化的。任何后续改动若引入
网络能力，`tools/check-repo.sh` 应同步加入对应检查项，防止合规前提被静默破坏。
