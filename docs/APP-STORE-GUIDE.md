# 鸿蒙应用市场上架指引

> 面向 CamelHump v1.1.1 及以后版本。本文按「先决条件 → 代码改造 → 打包 → 提交 → 过审后运营」的顺序写，
> 每一步都标了**卡点在哪**、**预计耗时**和**你必须自己做的动作**。

---

## 零、先看清一个关键事实

CamelHump 与市面上绝大多数待上架应用有一个根本区别：

> **它不联网。** 代码里没有任何 HTTP/Socket 调用，应用包内不申请任何权限，
> 模型权重由用户自行导入，推理在设备 CPU 上完成。

这个属性带来的直接后果：

| 监管项 | 是否需要 | 理由 |
| --- | --- | --- |
| 互联网信息服务算法备案 | **不需要** | 《深度合成管理规定》《算法推荐管理规定》均以「提供互联网信息服务」为前提。算法完全部署于本设备，不构成提供互联网信息服务，不适用备案与安全评估 |
| 生成式AI服务备案 | **不需要** | 《生成式AI服务管理暂行办法》排除「未向境内公众提供生成式AI服务」的研发和应用活动 |
| 大模型上线备案 / 登记 | **不需要** | 同上 |
| 增值电信业务经营许可证 | **不需要** | 不从事经营性互联网信息服务，无服务器、无收费 |
| 工信部 APP 备案 | **需在 AGC 填写** | 系统必填项。你的应用不指向境内服务器，理论上不属于「从事APP互联网信息服务」，但审核以系统是否放行为准，需按提示如实填写 |
| 软件著作权 | 非必选 | 华为明确标注为「非必选资质」，但建议申请（周期 20–40 工作日） |
| **AI 生成内容显式标识** | **必须** | 《人工智能生成合成内容标识办法》。华为要求提交「应用内已添加内容显式标识截图」 |

**结论：这个应用的上架难点不在资质，在素材和审核沟通。** 代码侧该做的合规改造已经做完了（见第二节）。

⚠️ **仍存在的不确定性**：华为审核是人工+规则混合的，对「AI 类应用」会走扩展审核流程。
审核员可能按「应用包含生成式AI功能」来要求全套材料，即使你的模型是用户自己导入的。
**如果被要求算法备案，最现实的处理是提供材料说明端侧部署的豁免情形**，或者按审核意见删除相关描述后重新提交。
提前准备好这段说明能省一轮往返：

> 本应用为纯端侧离线推理工具。模型权重由用户自行导入并在设备本地运行，
> 应用不含任何网络通信代码，不申请任何权限（含网络权限），
> 不向任何服务器传输用户输入或模型输出，不向不特定公众提供生成式AI服务。
> 依据《互联网信息服务深度合成管理规定》第二条「应用深度合成技术提供互联网信息服务适用本规定」，
> 本应用不构成提供互联网信息服务，故无需算法备案与安全评估。

## 一、账号与主体（前置条件，最耗时）

### 1.1 注册与实名认证

1. 访问 [华为开发者联盟](https://developer.huawei.com/consumer/cn/)，用华为账号注册
2. 完成**实名认证**：
   - **个人开发者**：身份证认证
   - **企业开发者**：营业执照认证

> **注意**：主体类型一旦选定**不可更改**。个人账号无法升级为企业账号。
> 若你已有企业主体，建议直接用企业认证——后续若要加云端能力或商业化，路径更顺。

### 1.2 「应用创建受邀名单」（可能阻塞）

社区反馈显示，2026 年起华为收紧了应用创建权限：新注册账号需申请加入**应用创建受邀名单**。

若在 AGC 创建应用时被拦：

1. 发送邮件至 `agconnect@huawei.com`
2. 邮件内容：说明用途 + 提供你的 **Developer ID**（开发者后台可见）
3. 处理时长通常 **3–5 个工作日**

> 这是流程中第一个可能卡住你的点，建议**第一天就发邮件**，不要等打包完再处理。

### 1.3 软件著作权（建议并行启动）

| 项 | 说明 |
| --- | --- |
| 周期 | 20–40 个工作日 |
| 材料 | 源代码前 30 页 + 后 30 页、用户手册/设计文档、申请表 |
| 主体要求 | 著作权人须与 AGC 开发者主体**一致**（个人开发者就用个人名义） |

**代码开源不影响申请软著**——软著保护的是代码表达形式，不影响你同时以 Apache-2.0 开源。

来源：https://github.com/shy1658/CamelHump （源码已完整公开，直接可提交）

## 二、代码侧合规改造（已完成 ✅）

本轮已完成并推送到 `main` 分支：

### 2.1 AI 生成内容显式标识

《人工智能生成合成内容标识办法》要求对 AI 生成的合成内容做显式标识。实现方式：

- **对话气泡标签**：每条 AI 回复气泡上方显示「AI 生成」边框标签
- **空状态提示**：「回复内容由本机模型生成，可能存在错误，请勿直接作为事实依据」
- **设置页说明**：关于区完整说明标识措施与「不涉及隐式标识」的原因

因为应用**不提供生成内容的文件导出/下载功能**，不产生文件元数据，因此走华为「二选一」中的
第一条路径——只需提交**《应用内已添加内容显式标识截图》**，不需要《人工智能生成合成内容标识说明函》。

> **你需要做的**：真机运行应用，截一张**含「AI 生成」标签的对话界面**图。

### 2.2 移除网络权限

原 `module.json5` 申请了 `ohos.permission.INTERNET` 和 `ohos.permission.GET_NETWORK_INFO`
（下载功能的遗留），但代码里零网络请求。这类「有权限无功能」是审核驳回高频项。

现已移除全部权限声明，应用包内**权限列表为空**。

### 2.3 隐私政策（已部署）

- 全文：`docs/privacy.html`（同时部署在 GitHub Pages）
- 线上地址：<https://shy1658.github.io/CamelHump/privacy.html>
- 应用内入口：设置 → 关于 → 隐私政策

内容覆盖：零网络请求声明、零信息收集清单、本地存储数据清单、AI 标识措施、
权限说明（不申请任何权限）、第三方组件许可、未成年人保护、政策变更、联系方式。

### 2.4 设置页新增信息

设置 → 关于区现在包含：作者、GitHub、爱发电、隐私政策、开源协议、
版本号、最低支持系统、推理引擎、**数据流向（全部本地处理 · 无网络请求）**。

## 三、打包（提交物是 .app，不是 .hap）

### 3.1 关键区别

| | `.hap` | `.app` |
| --- | --- | --- |
| 用途 | 单模块安装包 | **上架提交包** |
| 签名 | 调试证书可 | **必须正式发布证书** |
| 生成方式 | `assembleHap` | `assembleApp` |
| 产物路径 | `entry/build/default/outputs/default/` | `build/outputs/default/` |

> **Releases 上给用户下载的 `.hap` 不能直接上传 AGC。** 上架必须重新构建 `.app`。

### 3.2 获取正式发布证书（Release Profile）

自签调试证书**不能上架**。流程：

1. DevEco Studio → `Build > Generate Key and CSR`
   - Key Store File：新建 `.p12`（密码 ≥8 位，大小写+数字+特殊符号至少两类组合）
   - Alias、Password、Validity（建议 25 年以上）、Certificate 信息
   - 输出 `.p12` 与 `.csr`
2. AGC → 项目 →「证书、APP ID 和 Profile」→ 申请发布证书
   - 上传 `.csr`
   - 选择应用 → 配置 Profile → 勾选发布证书
   - 下载 `.cer` 与 `.p7b`
3. `build-profile.json5` 配置签名：

```json5
{
  "name": "release",
  "type": "OpenHarmony",
  "material": {
    "storeFile": "./keystore/release.p12",
    "storePassword": "***",
    "keyAlias": "***",
    "keyPassword": "***",
    "signAlg": "SHA256withECDSA",
    "profile": "./keystore/release.p7b",
    "certpath": "./keystore/release-cert.cer"
  }
}
```

### 3.3 命令行构建 .app

```bash
export PATH=/root/ohos-clt/command-line-tools/bin:$PATH
export DEVECO_SDK_HOME=/root/ohos-clt/command-line-tools/sdk
export DEVECO_NODE_HOME=/root/ohos-clt/command-line-tools/tool/node
export PATH=$DEVECO_NODE_HOME/bin:$DEVECO_SDK_HOME/default/openharmony/toolchains:$PATH

hvigorw assembleApp --mode module -p product=default \
  -p module=entry@default -p buildMode=release --no-daemon
```

产物：`build/outputs/default/CamelHump-1.1.1.app`

> **注意**：DevEco Studio 的 `Build APP(s)` 会把工程内所有 HAP 模块打进 APP。
> 本工程只有一个 `entry` 模块，无此问题。

## 四、提交审核

### 4.1 素材清单

| 素材 | 规格 | 现状 |
| --- | --- | --- |
| 应用图标 | 216×216 或 512×512 PNG，≤2MB，非动图 | ✅ `AppScope/resources/base/media/app_icon.png` |
| 应用截图 | 3–8 张，800×450 或 450×800 | ⬜ **需真机截图** |
| 应用名称 | 与包名、备案信息一致 | ✅ 驼峰 |
| 简短介绍 | ≤80 字（建议 ≤25 字） | ⬜ 见下 |
| 详细介绍 | ≤8000 字 | ⬜ 见下 |
| 隐私政策 URL | 可公开访问 | ✅ <https://shy1658.github.io/CamelHump/privacy.html> |
| 内容分级 | 问卷 | ✅ 全选「不含 objectionable content」 |
| AI 标识截图 | 显式标识界面 | ⬜ **需真机截图** |

**建议分类**：`工具` → `效率`（避开金融、医疗、教育、游戏等需要专项资质的类目）

### 4.2 文案建议

**简短介绍（≤25 字）**

```
手机本地运行 GGUF 大模型，离线对话，对话内容不出设备
```

**详细介绍**

```
驼峰是一款完全离线的本地大模型运行时。

它把 Ollama 在桌面上最有价值的三件事搬到了鸿蒙手机上：一条路径加载模型、
一份清单描述模型、一个稳定的推理接口对接上层。区别在于，它不需要 systemd 常驻守护进程、
不需要无限期后台权限、不需要包管理器——这些在手机管控策略下本来就走不通。

【核心能力】
· 导入你自己下载的 GGUF 模型，支持 Q4 / Q5 / Q8 等量化格式
· 全部推理在设备 CPU 上完成，不联网、不注册、对话内容不出设备
· 流式输出，中文不乱码（按 UTF-8 字符边界裁剪，不产生半个字符）
· 中途可随时停止生成
· 多模型管理：导入、切换、删除、容量统计，一键停止使用并卸载内存占用
· 上下文最长 128k，多轮对话复用 KV 缓存与 prompt 前缀
· CPU 侧四项优化：KV cache Q8_0 量化、Flash Attention、大核亲和性线程池、prompt cache 前缀复用
· 设置页显示引擎实际启用的配置，避免优化静默降级后无法排查

【隐私】
应用不包含任何网络通信代码，不申请任何权限（包括网络权限），
不收集设备标识、位置、通讯录等任何个人信息。
模型文件、对话记录、偏好设置全部保存在应用私有沙箱内，卸载即清除。
AI 生成的回复在界面上有明确的「AI 生成」标识。

【已知限制】
· 仅支持 GGUF，不支持 safetensors / GPTQ / AWQ / EXL2 / ONNX
· 应用内不提供模型下载，需自行获取模型文件后导入
· 暂不支持 GPU 推理（Vulkan compute）
· 受系统管控策略限制，无后台常驻能力

开源协议：Apache-2.0
源码：https://github.com/shy1658/CamelHump
```

### 4.3 审核备注（Review Notes）话术

审核备注直接决定通过率。建议写：

```
【功能说明】
本应用是纯端侧离线大模型推理工具。用户自行导入 GGUF 模型文件后，
应用在设备 CPU 上通过 llama.cpp 引擎进行本地推理。

【AI 能力说明】
1. 推理完全在设备本地完成，应用不含任何网络通信代码，不申请任何权限（含网络权限）
2. 模型权重由用户自行导入，不提供模型下载，不调用任何云端 API
3. 不向任何服务器传输用户输入或模型输出，不向不特定公众提供生成式AI服务
4. 依据《互联网信息服务深度合成管理规定》第二条，算法完全部署于本设备，
   不构成提供互联网信息服务，故无需算法备案与安全评估
5. 已按《人工智能生成合成内容标识办法》做显式标识：每条 AI 回复气泡上方标注
   「AI 生成」标签，应用不提供生成内容文件导出功能，不涉及文件元数据隐式标识
6. 已在「设置 - 关于」中提供隐私政策入口与完整说明

【合规材料】
· 隐私政策：https://shy1658.github.io/CamelHump/privacy.html
· AI 生成内容显式标识截图：见上传附件
· 应用内已添加内容显式标识（对应华为要求的第一种情形）

【测试账号】
无需登录，无账号体系。

【其他】
· 最低支持 HarmonyOS API 18
· 应用无广告、无内购、无账号、无埋点统计
```

## 五、过审后

### 5.1 备案信息

AGC 的「备案信息」区需填写备案号、主办单位、证件号，点击**「校验证件号」**校验。
**应用名称与包名必须与备案时完全一致**。

### 5.2 展示备案编号

若拿到了 APP 备案号，需在应用显著位置标明备案编号，并在编号下方链接备案系统网址。
建议位置：**设置 → 关于**区加一行 `备案号：XXX` 并可点击跳转。

### 5.3 首次发布建议

选择**延时发布**，把发布时间设到一个工作日的上午——这样万一被驳回，
有充足时间改，不至于卡在周末。

### 5.4 版本迭代

过审后的常规更新只需：改 `AppScope/app.json5` 的 `versionCode`（必须单调递增）、
重新签名、重新提交审核。

本工程的 `keystore/gen-signing.sh` 已支持通过环境变量指定版本号：

```bash
cd keystore && VERSION_NAME=1.2.0 VERSION_CODE=1001002 ./gen-signing.sh
```
