# 鸿蒙应用市场上架指引

> 面向 CamelHump v1.1.1 及以后版本。本文按「先决条件 → 代码改造 → 打包 → 提交 → 过审后运营」的顺序写，
> 每一步都标了**卡点在哪**、**预计耗时**和**你必须自己做的动作**。

---

## 零、先看清一个关键事实

CamelHump 与市面上绝大多数待上架应用有一个根本区别：

> **它不联网。** 代码里没有任何 HTTP/Socket 调用，应用包内不申请任何权限，
> 模型权重由用户自行导入，推理在设备 CPU 上完成。

这个属性带来的直接后果（依据官方《应用资质审核要求》与《APP核准(APP备案)指引》）：

| 监管项 | 是否需要 | 依据 |
| --- | --- | --- |
| **工信部 APP 备案** | **不需要** | 官方《APP核准(APP备案)指引》第 2 条：单机应用（未通过连接公共互联网提供互联网信息服务的移动应用程序）**无需备案**，在 AGC「备案信息」处勾选「**您的APP为单机APP**」即可 |
| **AI 生成内容显式标识** | **必须** | 《人工智能生成合成内容标识办法》。本应用不提供生成内容的文件导出，走官方「二选一」的第一条路径：提交《应用内已添加内容显式标识截图》 |
| 互联网信息服务算法备案 | 大概率不需要 | 《深度合成管理规定》《算法推荐管理规定》均以「提供互联网信息服务」为前提。算法完全部署于本设备，不构成提供互联网信息服务，不适用备案与安全评估 |
| 生成式AI服务备案 / 大模型登记 | 不需要 | 《生成式AI服务管理暂行办法》排除「未向境内公众提供生成式AI服务」的研发和应用活动 |
| 增值电信业务经营许可证 | 不需要 | 不从事经营性互联网信息服务，无服务器、无收费 |
| 软件著作权 | **非必选** | 官方原文：「APP软件著作权证书为『非必选资质』」。**本次决定不申请**（见 1.3 节） |
| 隐私声明（隐私政策 URL） | **必须** | 已在 GitHub Pages 部署 |
| 隐私权利网址 | **必须** | 见 5.3 节说明 |
| 华为账号登录 | 不适用 | 官方要求「支持三方账号登录的应用须提供华为账号登录选项」。本应用无账号体系，不触发该条 |

**结论：这个应用的上上架路径比绝大多数应用短得多。** 代码侧该做的合规改造已完成（第二节），
备案这一项直接勾选「单机APP」即可跳过。

⚠️ **唯一需要准备的说明**：审核员可能按「应用包含生成式AI功能」来要求全套材料。
官方《应用资质审核要求》对「深度合成或生成式人工智能服务」列了四项要求
（显式标识材料、算法备案查询截图、《安全评估报告》、安全评估报告提交结果截图）。
若被要求，提交下面这段说明，并附上显式标识截图：

> 本应用为纯端侧离线推理工具。模型权重由用户自行导入并在设备本地运行，
> 应用不含任何网络通信代码，不申请任何权限（含网络权限），
> 不向任何服务器传输用户输入或模型输出，不向不特定公众提供生成式AI服务。
> 依据《互联网信息服务深度合成管理规定》第二条「应用深度合成技术提供互联网信息服务适用本规定」，
> 本应用不构成提供互联网信息服务，故无需算法备案与安全评估。

> **单机APP 勾选的注意事项**（官方原文）：
> 「勾选『单机APP』提交版本审核后，若识别到该应用存在非以上特定联网场景，将无法通过审核，
> 会影响您的版本发布进度，请谨慎选择！」
>
> 官方认可的四种单机场景中，本应用属于「**完全离线型**：断网后，APP内所有功能和链接均可正常访问」。
> 唯一的例外是「仅隐私协议托管联网型」——隐私政策链接由系统浏览器打开，不经应用进程，
> 属于官方认可的豁免情形之一。但为稳妥起见，**不要在应用内嵌入 WebView 加载隐私政策**，
> 用系统浏览器打开可以避免被判定为联网场景。

## 一、账号与主体（前置条件，最耗时）

### 1.1 注册与实名认证

1. 访问 [华为开发者联盟](https://developer.huawei.com/consumer/cn/)，用华为账号注册
2. 完成**实名认证**：
   - **个人开发者**：身份证认证
   - **企业开发者**：营业执照认证

> **注意**：主体类型一旦选定**不可更改**。个人账号无法升级为企业账号。
> 若你已有企业主体，建议直接用企业认证——后续若要加云端能力或商业化，路径更顺。

### 1.2 「应用创建受邀名单」（可能阻塞）

社区反馈显示，2026 年起华为收紧了应用创建权限：新注册账号需申请加入**应用创建受邀名单**。

若在 AGC 创建应用时被拦：

1. 发送邮件至 `agconnect@huawei.com`
2. 邮件内容：说明用途 + 提供你的 **Developer ID**（开发者后台可见）
3. 处理时长通常 **3–5 个工作日**

> 这是流程中第一个可能卡住你的点，建议**第一天就发邮件**，不要等打包完再处理。

### 1.3 软件著作权（可跳过）

**结论：本次上架不申请软著。**

华为《应用资质审核要求》第 3 条明确写：「APP 软件著作权证书为『非必选资质』」，
不申请不影响提交审核。

除软著外的价值：
- 高新技术企业认定 / 双软认定
- 各地政府补贴（部分省市按登记费补贴，单件最高 800 元）
- 招投标项目的资质门槛

若日后确有刚需，注意 2026 年 3 月 15 日起的新规增加了手抄承诺
（「未使用 AI 开发编写代码、撰写文档或生成登记申请材料」）与失信惩戒机制，
对本项目存在口径风险。材料已备好于 [`docs/copyright/`](copyright/)，
可直接复用，详见 [`docs/copyright/软著申请指引.md`](copyright/软著申请指引.md)。

## 二、代码侧合规改造（已完成 ✅）

本轮已完成并推送到 `main` 分支：

### 2.1 AI 生成内容显式标识

《人工智能生成合成内容标识办法》要求对 AI 生成的合成内容做显式标识。实现方式：

- **对话气泡标签**：每条 AI 回复气泡上方显示「AI 生成」边框标签
- **空状态提示**：「回复内容由本机模型生成，可能存在错误，请勿直接作为事实依据」
- **设置页说明**：关于区完整说明标识措施与「不涉及隐式标识」的原因

因为应用**不提供生成内容的文件导出/下载功能**，不产生文件元数据，因此走华为「二选一」中的
第一条路径——只需提交**《应用内已添加内容显式标识截图》**，不需要《人工智能生成合成内容标识说明函》。

> **你需要做的**：真机运行应用，截一张**含「AI 生成」标签的对话界面**图。

### 2.2 移除网络权限

原 `module.json5` 申请了 `ohos.permission.INTERNET` 和 `ohos.permission.GET_NETWORK_INFO`
（下载功能的遗留），但代码里零网络请求。这类「有权限无功能」是审核驳回高频项。

现已移除全部权限声明，应用包内**权限列表为空**。

### 2.3 首次运行隐私政策授权弹窗 ✅ 新增

官方要求（《应用审核FAQ》与审核高频问题攻略）：

> 应用首次运行时需通过弹窗向用户申请授权展示隐私政策，用户同意隐私政策前应用不应该有任何
> 调用权限 API 的行为……审核会实测这一步。

原有实现**缺失**这一环，是本次排查发现的唯一硬性阻塞项。已补齐：

| 要求 | 实现 |
| --- | --- |
| 首次运行弹窗 | `entry/src/main/ets/view/PrivacyConsent.ets`，全屏遮罩层，盖在主界面之上不可穿透 |
| 不得默认勾选 | `Checkbox` 初始 `agreed = false`，未勾选时「同意并继续」按钮为禁用态 |
| 须有「不同意」选项 | 「不同意并退出」按钮，调用 `terminateSelf()` 关闭应用 |
| 同意前不碰本地数据 | `AppStore.boot()` 在未同意时**只读同意标志**，不读设置、不读模型清单；同意后才调 `loadAfterConsent()` |
| 弹窗不遮挡勾选状态 | 自绘弹窗，不用系统 AlertDialog —— 系统弹窗放不下复选框，易被判为「默认勾选」 |
| 隐私政策可查看 | 弹窗内「《隐私政策》」链接，用**系统浏览器**打开（`ContextHolder.get().openLink()`） |

> 为什么用系统浏览器而不是应用内 WebView：官方认可的「单机应用」场景中
> 「仅隐私协议托管联网型」是豁免情形之一，但用系统浏览器更稳妥，
> 不会被判定为应用存在联网场景（勾选「单机APP」时的风险点）。

同意状态存储键：`camelhump.privacy.consent.v1`（`Config.ets` 的 `PRIVACY_CONSENT_KEY`）。

## 三、打包（提交物是 .app，不是 .hap）

### 3.1 关键区别

| | `.hap` | `.app` |
| --- | --- | --- |
| 用途 | 单模块安装包 | **上架提交包** |
| 签名 | 调试证书可 | **必须正式发布证书** |
| 生成方式 | `assembleHap` | `assembleApp` |
| 产物路径 | `entry/build/default/outputs/default/` | `build/outputs/default/` |

> **Releases 上给用户下载的 `.hap` 不能直接上传 AGC。** 上架必须重新构建 `.app`。

### 3.2 获取正式发布证书（Release Profile）

自签调试证书**不能上架**。流程：

1. DevEco Studio → `Build > Generate Key and CSR`
   - Key Store File：新建 `.p12`（密码 ≥8 位，大小写+数字+特殊符号至少两类组合）
   - Alias、Password、Validity（建议 25 年以上）、Certificate 信息
   - 输出 `.p12` 与 `.csr`
2. AGC → 项目 →「证书、APP ID 和 Profile」→ 申请发布证书
   - 上传 `.csr`
   - 选择应用 → 配置 Profile → 勾选发布证书
   - 下载 `.cer` 与 `.p7b`
3. `build-profile.json5` 配置签名：

```json5
{
  "name": "release",
  "type": "OpenHarmony",
  "material": {
    "storeFile": "./keystore/release.p12",
    "storePassword": "***",
    "keyAlias": "***",
    "keyPassword": "***",
    "signAlg": "SHA256withECDSA",
    "profile": "./keystore/release.p7b",
    "certpath": "./keystore/release-cert.cer"
  }
}
```

### 3.3 命令行构建 .app

```bash
export PATH=/root/ohos-clt/command-line-tools/bin:$PATH
export DEVECO_SDK_HOME=/root/ohos-clt/command-line-tools/sdk
export DEVECO_NODE_HOME=/root/ohos-clt/command-line-tools/tool/node
export PATH=$DEVECO_NODE_HOME/bin:$DEVECO_SDK_HOME/default/openharmony/toolchains:$PATH

hvigorw assembleApp --mode module -p product=default \
  -p module=entry@default -p buildMode=release --no-daemon
```

产物：`build/outputs/default/CamelHump-1.1.1.app`

> **注意**：DevEco Studio 的 `Build APP(s)` 会把工程内所有 HAP 模块打进 APP。
> 本工程只有一个 `entry` 模块，无此问题。

### 4.2 文案建议

**简短介绍（≤25 字）**

```
手机本地运行 GGUF 大模型，离线对话，对话内容不出设备
```

**详细介绍**

```
驼峰是一款完全离线的本地大模型运行时。

它把 Ollama 在桌面上最有价值的三件事搬到了鸿蒙手机上：一条路径加载模型、
一份清单描述模型、一个稳定的推理接口对接上层。区别在于，它不需要 systemd 常驻守护进程、
不需要无限期后台权限、不需要包管理器——这些在手机管控策略下本来就走不通。

【核心能力】
· 导入你自己下载的 GGUF 模型，支持 Q4 / Q5 / Q8 等量化格式
· 全部推理在设备 CPU 上完成，不联网、不注册、对话内容不出设备
· 流式输出，中文不乱码（按 UTF-8 字符边界裁剪，不产生半个字符）
· 中途可随时停止生成
· 多模型管理：导入、切换、删除、容量统计，一键停止使用并卸载内存占用
· 上下文最长 128k，多轮对话复用 KV 缓存与 prompt 前缀
· CPU 侧四项优化：KV cache Q8_0 量化、Flash Attention、大核亲和性线程池、prompt cache 前缀复用
· 设置页显示引擎实际启用的配置，避免优化静默降级后无法排查

【隐私】
应用不包含任何网络通信代码，不申请任何权限（包括网络权限），
不收集设备标识、位置、通讯录等任何个人信息。
模型文件、对话记录、偏好设置全部保存在应用私有沙箱内，卸载即清除。
AI 生成的回复在界面上有明确的「AI 生成」标识。

【已知限制】
· 仅支持 GGUF，不支持 safetensors / GPTQ / AWQ / EXL2 / ONNX
· 应用内不提供模型下载，需自行获取模型文件后导入
· 暂不支持 GPU 推理（Vulkan compute）
· 受系统管控策略限制，无后台常驻能力

开源协议：Apache-2.0
源码：https://github.com/shy1658/CamelHump
```

## 五、过审后

### 5.1 备案信息：勾选「单机APP」

本应用无需备案。在 AGC 的「APP核准(备案)」区域，选择：

> **您的APP为单机APP**

依据官方《APP核准(APP备案)指引》第 2 条：

> 如您的应用为单机应用，可选择「您的APP为单机APP」。您需要提前了解我们对单机应用和境外应用的要求。
> 单机应用定义：未通过连接公共互联网提供互联网信息服务的移动应用程序。

官方列举的四种单机场景中，本应用符合「**完全离线型**：断网后，APP内所有功能和链接均可正常访问」。

> ⚠️ **谨慎勾选**（官方原文）：
> 「勾选『单机APP』提交版本审核后，若识别到该应用存在非以上特定联网场景，将无法通过审核，
> 会影响您的版本发布进度，请谨慎选择！」
>
> 提交前自检：断网后打开应用，确认模型导入、加载、对话全部正常。
> 不要在应用内嵌入 WebView，也不要引入任何联网 SDK。

### 5.2 隐私权利网址

官方列为必备材料：「需提交关于用户实施其权利的相关网站，如用户删除、修改、导出其个人数据的入口」。

本应用的情况：用户可自行删除模型、清除对话、卸载应用（沙箱数据全部清除），
这些操作都在应用内完成，无账号体系故无「导出个人数据」的诉求。
隐私政策页已说明「卸载应用即一并清除全部本地数据」，可作为该栏位的答复。

若 AGC 强制要求填 URL，填写隐私政策地址即可：
<https://shy1658.github.io/CamelHump/privacy.html>

### 5.3 展示备案编号

单机应用无备案号，**不需要**在应用内展示备案编号。
若后续版本增加了联网能力并完成备案，需在应用显著位置标明备案编号，
并在编号下方链接备案系统网址。建议位置：**设置 → 关于**区加一行 `备案号：XXX`。

### 5.4 首次发布建议

选择**延时发布**，把发布时间设到一个工作日的上午——这样万一被驳回，
有充足时间改，不至于卡在周末。

### 5.4 版本迭代

过审后的常规更新只需：改 `AppScope/app.json5` 的 `versionCode`（必须单调递增）、
重新签名、重新提交审核。

本工程的 `keystore/gen-signing.sh` 已支持通过环境变量指定版本号：

```bash
cd keystore && VERSION_NAME=1.2.0 VERSION_CODE=1001002 ./gen-signing.sh
```
