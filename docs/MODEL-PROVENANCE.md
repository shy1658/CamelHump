## 一、一句话结论

**驼峰不分发任何模型权重。应用安装包内不含任何模型文件，模型由用户自行从
第三方来源获取后通过系统文件选择器导入，推理 100% 在用户设备 CPU 上完成。
开发者既不提供模型下载服务，也不经手、不存储、不传输任何模型文件。**

---

## 二、模型从哪来：完全由用户自备

### 2.1 应用不内置、不附带、不分发模型

| 环节 | 事实 | 可核查依据 |
| --- | --- | --- |
| 安装包内模型文件 | **0 个** | `entry/src/main/resources/base/media/` 下仅有 `app_icon.png`、`startIcon.png`；模型目录 `models/` 在运行时由应用创建 |
| 应用内模型下载功能 | **不提供** | 全仓检索无 HTTP 客户端，`Config.ets` 中的 `CURATED_MODELS` 仅作**指引清单**，不含下载逻辑 |
| 开发者托管的模型仓库 | **不存在** | 开发者无服务器、无 CDN、无对象存储；源码中不存在任何指向自有服务端的地址 |
| 模型文件的上传通道 | **不存在** | 应用无任何网络能力，无法上传任何文件 |

### 2.2 唯一合法的模型获取路径：用户本地文件导入

完整链路（源码位置）：

```
用户自行下载 GGUF 文件（数据线 / 网盘 / 微信文件传输 / 浏览器另存）
        ↓
ModelsView.ets → pickGgufFile()              // 系统文件选择器，用户主动触发
        ↓
ModelRepository.ets: fs.openSync(uri, READ_ONLY)  // 只读取用户选中的那一个文件
        ↓
ModelRepository.ets: fs.writeSync(...)             // 复制到应用沙箱 models/ 目录
        ↓
GgufInspector（原生层）→ 解析头部 → 完整性校验
        ↓
InferenceEngine → llama.cpp 本地推理
```

关键点：

- 文件访问通过 **HarmonyOS 系统文件选择器**（`@kit.CoreFileKit` 的 `picker`），
  由用户主动触发，**仅授予单次访问所选文件的权限**，不涉及相册、存储等广泛授权。
- 复制后模型存放在**应用私有沙箱目录**（`filesDir/models/<id>/model.gguf`），
  卸载应用即一并清除，用户也可在应用内主动删除。
- 应用**不校验、不背书**模型内容，只做**格式与完整性校验**（GGUF 魔数、张量表
  与实际文件大小比对），目的是防止损坏文件导致推理崩溃，不是内容审核。

### 2.3 内置指引清单的性质

`Config.ets` 中的 `CURATED_MODELS` 是一份**静态字符串常量**，列出 3 个
Qwen2.5 GGUF 模型的名称、参数量、量化格式、体积、ModelScope 镜像地址与内存门槛。

必须明确：这是一份**帮助用户挑选模型的参考清单**，不是下载源。

- 清单里的 URL 指向 **ModelScope 公开仓库**（阿里巴巴开源社区），不是开发者自有服务器；
- 应用**从未请求过这些 URL**，代码中没有任何一处读取该数组发起网络请求；
- 该清单在应用内仅用于展示"推荐模型"条目与体积/内存提示；
- 清单中 `sha256` 字段为空字符串——应用**不提供**下载后的哈希校验，因为应用不下载。

> 审核提示：若审核员询问"应用如何获取模型"，标准回答是——
> **"应用不获取模型。用户自行获取 GGUF 文件后通过系统文件选择器导入。"**
> 清单里的 URL 仅供用户自行前往，不产生任何应用侧网络行为。

## 三、模型来源的法律责任划分

### 3.1 开发者侧

- 开发者**不训练、不微调、不分发**任何模型权重；
- 开发者**不提供**模型下载服务，**不运营**任何模型分发渠道；
- 应用内不含任何模型权重文件，因此**不存在**"提供者擅自提供他人模型"的问题；
- 应用代码遵循 Apache-2.0，推理引擎 llama.cpp 遵循 MIT（详见仓库 `NOTICE`）。

### 3.2 用户侧

模型权重的**来源合法性、许可协议、以及是否允许用户以自选方式使用**，完全由
用户自行判断。应用已在两个位置明示这一责任边界：

| 位置 | 文案 |
| --- | --- |
| `docs/privacy.html` 第六节 | 「模型权重内容完全由你选择的第三方来源决定，其训练数据、许可协议与输出结果均不属于本应用的控制范围，也不由开发者承担责任。请在导入前确认模型来源合法、许可协议允许你的使用方式（例如遵守模型作者要求署名或开放许可条款）。」 |
| 设置页 → 关于 | 同等口径的简短说明 |

### 3.3 常见的合规模型（供参考，非应用内置）

用户自选范围内最常见的 GGUF 模型及其许可：

| 模型 | 许可 | 说明 |
| --- | --- | --- |
| Qwen2.5 (0.5B / 1.5B / 3B Instruct) | Apache-2.0 | 阿里通义千问系列，开源许可宽松 |
| Qwen3 系列 | Apache-2.0 | 同上 |
| Llama 系列（Meta Llama Community License） | 自定义社区许可 | 有命名、附加条款与月活阈值要求 |
| Mistral / Phi / Gemma 等 | 各不相同 | 需逐一查阅模型卡 |

> 应用**不捆绑**其中任何一个，也**不主动分发**。用户导入即视为其自行完成
> 许可确认——这是"用户自导入模型"模式在合规上的核心意义。

## 四、"纯本地、用户自导入模型"能否替代算法备案号

> 这是本材料包中最需要向 AGC 确认的问题。以下是我方的论证基础，
> 最终以审核方的正式答复为准。

### 4.1 结论倾向

**倾向于"不需要"，且理由是法条级的、而非解释性的。** 核心逻辑：

```
《生成式人工智能服务管理暂行办法》第二条
  适用条件 = 利用生成式 AI 技术「向中华人民共和国境内公众提供」生成内容的服务
                                    ↓
  驼峰是否满足「向境内公众提供」？
    ├── 提供者主体？  → 无运营主体、无服务器、不发布服务给公众下载使用
    ├── 服务形态？    → 单机 APP，用户自行下载安装、仅供本人/本机使用
    ├── 网络可达性？  → 无网络权限、无网络 API，物理上不具备服务公众的能力
    └── 结论          → 不构成「向境内公众提供生成式人工智能服务」
                                    ↓
  不适用 → 不触发备案 / 登记义务
```

《互联网信息服务算法推荐管理规定》的算法备案义务同样以
**「具有舆论属性或者社会动员能力的互联网信息服务」**为前提。单机离线 APP
不具备舆论属性，也不构成互联网信息服务。

### 4.2 支撑材料清单（提交给审核方）

| # | 材料 | 位置 |
| --- | --- | --- |
| 1 | 无网络请求举证截图（module.json5 全文 + 全仓核查结论） | `docs/store-assets/network-proof.png` |
| 2 | 端侧推理架构图（四层调用栈 + 无网络阻断带） | `docs/store-assets/arch-diagram.png` |
| 3 | 本文档（模型来源说明） | `docs/MODEL-PROVENANCE.md` |
| 4 | 隐私政策（零网络请求声明、零信息收集清单） | `docs/privacy.html` |
| 5 | 源码仓库（可自行核查全部网络相关代码） | <https://github.com/shy1658/CamelHump> |
| 6 | AI 生成内容显式标识截图 | `docs/store-assets/ai-label-shot.png` |
| 7 | 标识与备案适用性论证 | `docs/AGC-ALGO-FILING-CONSULT.md` |

### 4.3 仍需谨慎的边界

诚实地说，有三点不能自行拍板，必须由审核方给出明确口径：

1. **"单机 APP"与"向公众提供"的关系。** 华为应用市场是**面向公众的分发渠道**，
   应用通过市场安装后是否会因此被认定为"向公众提供生成式 AI 服务"，
   这属于审核方的自由裁量。本材料的立场是：**分发渠道 ≠ 服务提供**，
   被分发物是一个不含模型、不含服务、不含联网能力的离线工具。
2. **"用户自导入模型"是否会被穿透认定为"应用提供模型服务"。** 我方立场是**否**，
   因为模型是用户自行获取的第三方文件，应用既不分发也不控制其内容。
   但若审核方认为需要"应用侧模型来源证明"，则可提供第 2.3 节表格。
3. **未来若加入模型下载功能，本结论立即失效。** 一旦应用引入网络能力并
   自行向用户提供模型，"纯本地"的论证基础不复存在，届时须走
   「直接调用已备案模型 → 应用登记」或「自研/部署 → 服务备案」路径。

## 六、附：可复核的核查命令

审核方或第三方可用以下命令自行复核本说明的全部事实主张：

```bash
# 1. 安装包内无模型文件
find entry/src/main/resources -name "*.gguf" -o -name "*.bin" -o -name "*.safetensors"
#    → 无输出

# 2. 无网络 API
grep -rniE "http|WebSocket|fetch\(|XMLHttpRequest|socket" \
  --include="*.ets" --include="*.cpp" --include="*.h" entry/src/main/
#    → 仅命中注释与变量名，无 API 调用

# 3. 无权限声明
grep -rn "ohos.permission" --include="*.json5" .
#    → 无输出

# 4. 无第三方依赖
cat oh-package.json5 | grep -A2 dependencies
#    → dependencies: {}
```
